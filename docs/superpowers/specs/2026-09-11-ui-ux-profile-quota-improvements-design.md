# UI/UX改善・プロフィール一元管理・ノルマ連打＆放置対策 設計仕様書

## 1. 概要と背景

### 課題
1. **未ログイン時の管理画面アクセス不可**:
   アプリ起動時にプロフィール選択画面が表示されるが、誰かのプロフィールを選んでログインしないと保護者ダッシュボードに入れない。
2. **プロフィールの編集制限**:
   各ユーザーとしてログインしなければそのユーザーのプロフィールを編集できないため、保護者が複数のお子様の設定を一括で確認・変更しにくい。
3. **ノルマの連打抜け穴**:
   問題数ノルマ（または科目別目標の問題数）が、選択肢を適当に連打して不正解を連発してもカウントされて達成できてしまう。
4. **時間ノルマの放置抜け穴**:
   画面を開いたまま放置しても、セッション時間として積算され、何もしなくても目標学習時間を達成できてしまう。
5. **全体的なUI/UXの分かりやすさ**:
   お子様にとっても保護者にとっても、直感的に状況（残り目標、操作方法）が伝わるデザインが求められている。

### 目的
1. **管理画面へのダイレクトアクセス**:
   どのプロフィールにもログインせずに、プロフィール選択画面から直接保護者パスワードで管理画面に入れるようにする。
2. **管理画面での全プロフィール一元管理**:
   管理画面内で全プロフィールの一覧表示、編集（名前・生年月日・学年・学期制・PIN・アバター）、新規作成、削除を完結できる。
3. **ノルマ連打対策（アクティブ学習認定）**:
   早押しガード（0.8秒インターバル）を導入し、ノルマ達成判定に「セッション正答率50%以上」を適用して、当てずっぽうな連打での達成を防止する。
4. **時間ノルマ放置対策（アクティブ時間計測）**:
   1問あたりの学習時間上限（最大40秒キャップ）、未回答タイムアウト時間の除外、2問連続放置による自動一時停止（休憩中ポップアップ）を導入する。
5. **UI/UXの向上**:
   操作性の向上、親しみやすいアニメーションやガイダンス表示、進捗状況の分かりやすいメッセージ化。

## 2. 管理画面ダイレクトアクセス ＆ プロフィール一元管理

### 2.1 プロフィール選択画面（`ProfileSelectorModal.tsx`）
- **直接アクセスボタンの配置**:
  - モーダル右上に「⚙️ 保護者管理画面へ」ボタンを配置。
  - クリックすると保護者パスワード入力画面を表示。
  - 認証通過後、特定のプロファイルでログインすることなく、管理画面を開く。
  - 管理画面を閉じた際（`onClose`）は、元のプロフィール選択画面に自然に戻る。
- **全プロフィール編集の保護者解放**:
  - 保護者認証が通過している状態であれば、プロフィール選択画面内でも全プロフィールの「へんしゅう ✏️」ボタンが使用可能になる。

### 2.2 管理画面（`ParentDashboard.tsx`）でのプロフィール管理機能
- **「👥 お子様・プロフィール管理」タブ/セクションの新設**:
  - 管理画面上部にタブナビゲーション（「📊 今日の進捗＆レポート」「🎯 ノルマ・ご褒美設定」「👥 プロフィール管理」「⚙️ 保護者設定」）を導入。
  - 「👥 プロフィール管理」では、登録されている全お子様の一覧をカード形式で表示：
    - アバター・名前・学年・生年月日・学期制・PIN保護状態
    - 「編集」ボタンでフォームを開き、即座に修正・保存可能。
    - 「＋ 新しいお子様を追加」ボタンで管理画面内から直接追加可能。
    - 「削除」ボタンでお子様を削除可能（1名のみの場合は削除不可）。
  - プロフィール更新後は即座に `storage.updateProfile()` が呼ばれ、同期される。

## 3. ノルマ連打対策（適当押し・高速回答防止）

### 3.1 クイズ画面（`QuizScreen.tsx`）の早押しガード
- **出題インターバル**:
  - 問題が表示されてから `800ms` の間は選択肢ボタンのクリックを無効化（誤タップ・連打防止）。
  - 各問題の回答にかかった所要時間を記録。
- **極端な早押しの検知**:
  - 1問の思考時間が 1.0 秒未満の回答については「しっかり問題文を読んでみよう！👀」と優しいガイダンスを表示。
- **解説画面のワンテンポ確認**:
  - 間違えた際の解説画面では、「つぎへ」ボタンの表示を少し工夫し、反射的なスキップ連打を抑制。

### 3.2 ノルマ達成判定（`src/utils/goalEvaluator.ts`）の適正化
- **正答率50%以上の適用**:
  - `checkIsDailyGoalAchieved` において、問題数ベースのノルマ達成判定に「その日の対象セッション全体の正答率が50%以上」を必須条件として加える。
  - 4択問題で何も考えず連打した場合、確率的に正答率は約25%前後となるため、連打では絶対にノルマを達成できない。
  - 一方で、普通に問題に向き合って解く場合は正答率50%以上は容易に達成でき、子どもの努力を阻害しない。

## 4. 時間ノルマ放置対策（アクティブ時間計測）

### 4.1 時間キャップ ＆ タイムアウト除外
- **1問あたりの時間上限キャップ（最大40秒）**:
  - クイズ画面を開いたまま放置しても、1問あたりにカウントされる学習時間は最大40秒で頭打ちとする。
- **未回答タイムアウト時間の除外**:
  - 30秒の制限時間内に回答せずタイムアウトになった問題は「放置」とみなし、その問題の所要時間は学習セッションの有効学習時間（`durationMinutes`, `durationSeconds`）に加算しない。

### 4.2 アイドル検知・自動一時停止
- **2問連続放置での自動一時停止**:
  - 2問連続で未回答タイムアウトとなった場合、クイズ画面を「🍵 きゅうけいちゅう」モーダルで自動一時停止。
  - タイマー・カウントを完全に停止し、画面上の「つづける 👉」ボタンを押すまで再開しない。
- **タブ切り替え・画面非アクティブ検知**:
  - ブラウザの `visibilitychange` イベントにより、別タブやバックグラウンドになった際はタイマーを一時停止。

## 5. UI/UX向上 ＆ デザイン改善

### 5.1 ホーム画面・目標進捗表示の改善
- **具体的な次のアクション表示**:
  - ノルマ進捗バーの横に「あと◯問正解でクリア！」「あと◯分集中しよう！」という、子どもにも直感的にわかる応援メッセージを表示。
- **達成時の演出**:
  - 目標達成時のお祝いメッセージとアニメーションの視認性向上。

### 5.2 操作性とビジュアルの洗練
- **レスポンシブなカードデザイン**:
  - タブレットやスマートフォンでも見やすく、タップしやすい余白とボタンサイズ。
- **安心感のあるカラーパレット**:
  - 管理画面と学習画面で一貫した親しみやすいデザインシステムを維持。
